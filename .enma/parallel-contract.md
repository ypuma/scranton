# Parallel / sandbox implementation contract (Core, 2026-11-08)

Authoritative integration decisions; implementation lanes may propose changes via Core, not silently diverge.

## Runtime and configuration

Runtime modules: core/tools (contained deterministic tools/schemas/truncation), core/llm (own clients), core/credentials (own store/OAuth/import), core/durable (SQLite or real DBOS), core/agent (workflow runner). Current task ownership is assigned per task, not by the original migration lane matrix.

Defaults: execution.maxParallel=3, isolation=worktree, sandbox.mode=scranton, sandbox.network=allow, persistentSessions=true, maxReplans=0. Docker is an optional tool-only executor (scranton-tools:24-r1), host requires explicit trust. No fallback/download/install. Shared mode needs explicit host and maxParallel:1. Windows Low uses PowerShell instead of Bash and rejects network:none. Full OS limitations: docs/ISOLATION.md. CLI/API fields: run-options-contract.md.

Plans: omitted dependsOn means predecessor (first -> []); explicit [] is independent. Reject malformed/unknown/self/cyclic dependencies. Only QA plus safe integration satisfies an edge. Skipped/failed prerequisites block successors. maxParallel counts milestone pipelines, not roles.

Instances use exact IDs (michael, dwight-m1, angela-m1, custom gates). Session UUIDs are identities; durable history is per workflow, not Pi JSONL or automatic cross-invocation reuse. Orchestrator supplies deterministic milestone/cycle/role/purpose/attempt keys. Retain database and at-most-once markers together. Whole-run automatic resumption is not implemented.

## Runtime integration

Orchestrator defaults startRunner to startAgent. Interface, callbacks, identity, streams, approvals and reattachment: agent-stream-contract.md. It prepares native/Docker executor, injects sandbox.spawn, and awaits disposal before cleanup/lease release. Low-level startAgent defaults to direct spawn; API callers are responsible for isolation. Pi execution overrides, pi.* and extraArgs are rejected. No CLI/RPC process or extension discovery.

agent_chat is an own tool. sendMessage returns delivered only after durable steering queue acceptance, not model consumption. Incoming/idle queue belongs to ChatRouter. Uncertain attempted sends must never replay automatically. Role prompts and instance mailbox input are host-side workflow inputs, never a Docker mount or task argv interpolation.

## Worktree integration
`new WorktreeManager({workspace,hiveDir,runId}); await manager.init()`; PRIVATE shadow Git repo under managed run storage, no writes to user's .git refs/index/HEAD. Snapshot dirty/unborn/non-Git working content. Exclude credentials, .git, managed Hive/worktree/runtime dirs, ignored deps/builds; reject links/reparse paths that escape. Every role including planner gets isolated worktree.
`createWorktree({agent,milestoneId,baseRef?})->{dir,ref}` (planner milestoneId can be 'plan'); defaults to latest integrated snapshot.
`snapshotWorktree({agent,milestoneId})->ref` captures completed developer content.
`createQaWorktree({milestoneId})->{dir,ref}` from EXACT developer snapshot; QA mutations never integrated.
`integrateToTarget({milestoneId,workspace?})->result` serializes verified snapshot integration. Preserve user index/history/dirty baseline and concurrent user edits, detect overlapping conflicts, binary/deletion support, validate all target paths/reparse components, preflight all files before applying and rollback partial I/O errors. Never overwrite conflict. Update private integrated baseline for subsequent dependency worktrees. Retain artifacts for failed/aborted runs; cleanup never removes user work. `close()` cleanup owned resources only, preserve diagnostic worktrees by default.

## Events / UI contract (additive event v1)
Keep `currentMilestoneId` scalar; add `activeMilestoneIds: string[]`. Existing role aggregates remain; add `instances: {[id]:{id,agent,milestoneId,status,tool,sessionId,worktree,sandbox}}`.
Existing agent_status/agent_tool/agent_finished gain instanceId; instance_started event includes instanceId,agent,milestoneId,sessionId,worktree,sandbox. Event run_started gains execution. plan_ready includes dependsOn; milestone fields gain dependency/state data. Preserve old consumer schema and totals.
Chat: `chat_message {id,from,to,text,milestoneId?,delivery:'queued'|'delivered'|'rejected'|'unknown',reason?}` and `chat_delivery {id,delivery,reason?}`; bounded `state.chat` array. Sender instance from runner, human from control route. Recipient exact instance ID; unknown or terminal instances rejected clearly, no arbitrary role ambiguity. Durable journal/idle queue: queued means never sent. Attempted sends leave the replay queue; timeout/cancel or thrown/invalid ACK becomes unknown, definitive negative ACK rejected. Emit/journal unknown and return ok:false/error; never automatically replay uncertain sends after detach/attach/finish. Tool chat callback deadline: 10 s; no RPC startup protocol. Live delivery uses sendMessage; don't return delivered until acknowledged. chat_command_rejected is separate uncorrelated diagnostics for malformed/stale/duplicate commands, never a transcript update. Bound text/count to avoid runaway model chatter.
HITL serialized across lanes; head request only in human/response.json, remaining visible as queued count if feasible. Other independent milestones can continue; role aggregates must not erase active lanes. Abort cancels queued questions and all active processes.
Dynamic replanning is not implemented. The published DAG is immutable; effective maxReplans is 0 and nonzero configured values warn rather than enabling replanning.

## Server / control
POST /api/runs optional fields: `maxParallel`, `sandbox` ('scranton'|'docker'|'host'), `sandboxImage`, `sandboxNetwork` ('allow'|'none', bridge alias); host requires `trustedHost:true`. Forward to CLI flags. GET /api/control adds defaults.execution plus `instances` (from state), `recoveryRequired` and recovery metadata where needed.
POST /api/chat body `{runId,to,text}` writes unique atomic command under hive/control/chat/*.json. Response is queued, never falsely delivered; orchestrator consumes and emits chat_message/chat_delivery. Requires same loopback/Host/CSRF checks, active matching run, recipient validation, size limits. No standalone CLI `message` command is implemented; server/tool chat is supported.
Durable run lease: lifecycle module src/core/run-lease.js actual disk owner.json (do not use researcher's guessed lease.json). Server generates SCRANTON_RUN_ID before spawn for BOTH run/demo, use stdio ['pipe','pipe','pipe','ipc'] and env SCRANTON_PARENT_GUARD=1 + SCRANTON_RUN_LEASE. CLI calls registerParentStartup before parsing/config, awaits begin() (scranton-startup-begun) before work and calls refuse() (scranton-startup-refused) on every pre-work exit. guardParent sends scranton-guard-registered. IPC messages carry the lease token. Server releases after child close only with matching refusal and no begun/guard registration; missing or contradictory startup evidence retains the lease. Spawn failure before a PID can safely release. `guardParent({hiveDir,abort,stdin=process.stdin,env=process.env})->dispose({clean=false}={})`; install BEFORE work; EOF/error aborts. Dispose clean only after ALL children/containers stopped. Standalone ownership uses acquireRunLease(hiveDir, info) / releaseRunLease(hiveDir, token). All CLI modes writing Hive must exclude simultaneous owners, including independent CLI vs desktop. Unknown cleanup remains fail-closed, never blind stored-PID kill.
