## Configuration and behavior
`execution: { maxParallel: 3, isolation: 'worktree', sandbox: { mode: 'docker', image: 'scranton-sandbox:1.5.0', network: 'bridge' }, persistentSessions: true, maxReplans: 0 }`.
Real runs default to RPC+worktrees+docker. Explicit `--trusted-host` switches sandbox to host (worktrees still used); no silent fallback. Legacy shared mode requires explicit host configuration and maxParallel:1; shared+Docker rejects, and instance worktree metadata is null. Fake-pi demos use deterministic fake RPC/host with isolated scratch worktrees as practical; must label simulated/trusted-host accurately. Config validation rejects maxParallel>1 without worktree isolation. CLI supports --parallel N, --trusted-host, --sandbox docker, --sandbox-image IMAGE (and optional --sandbox-network none|bridge). `doctor` reports engine/image unavailability honestly. No installs or actual Docker builds on this host (no engine exists).

Plans: omitted dependsOn on milestone i means predecessor (i=0 -> []); EXPLICIT [] means independent. Reject malformed/unknown/self/cyclic deps. Skipped/failed prerequisites must NOT count as passed and must block dependent work. Safe integration occurs before dependency is satisfied. maxParallel counts active milestone pipelines (one dev or QA process each) not number of fixed role names.

Instances: planner `michael`; milestone agents `dwight-m1`, `angela-m1`, etc. Stable instance IDs and UUID session IDs per run/instance. Mailboxes/session files per instance; retain role aliases only for legacy readers, never use them for concurrent transport. Persistent retries use the same session ID and directory; per invocation RPC process may close after final agent_settled, session persists on disk.

## Runtime integration
Preserve startPi(options)->{done,kill}; RPC options transport:'rpc', instanceId, sessionId, onMessage:async({to,text})=>ack. Returned sendMessage(text) resolves with a positive ACK, definitive rejection or delivery:'unknown' on steer ACK timeout/cancellation; no forgeable sender/run inputs. Implement managed model-callable `agent_chat` extension with honest broker ACK via supported RPC extension UI or equivalent protocol. Incoming/idle queue is router responsibility.
`options.execution` optional launch override: `{spec,argsPrefix,cwd,env,systemPromptFile,sessionDir,extensionFile,inboxFile,cleanup}`. Runtime applies overridden paths when building args, argsPrefix before pi flags, and always waits for cleanup on done/kill. In RPC, read inbox content on host, send initial prompt through stdin. Never mount all Hive or interpolate task text into argv.
Isolation exports `prepareSandbox({sandbox,workspace,sessionDir,systemPromptFile,extensionFile,env,instanceId,runId})` returning execution override; host mode returns suitable identity override. `checkSandbox(sandbox)` returns/report availability; `buildSandboxImage` optional explicit CLI support. Sandbox stage files created on host before preparation. Coordinate exact timing with Core if runner currently writes system prompt internally.

Snapshot dirty/unborn/non-Git working content. Exclude credentials, .git, managed Hive/worktree/runtime dirs, ignored deps/builds; reject links/reparse paths that escape. Every role including planner gets isolated worktree.
`createWorktree({agent,milestoneId,baseRef?})->{dir,ref}` (planner milestoneId can be 'plan'); defaults to latest integrated snapshot.

`integrateToTarget({milestoneId,workspace?})->result` serializes verified snapshot integration. Preserve user index/history/dirty baseline and concurrent user edits, detect overlapping conflicts, binary/deletion support, validate all target paths/reparse components, preflight all files before applying and rollback partial I/O errors. Never overwrite conflict. Update private integrated baseline for subsequent dependency worktrees. Retain artifacts for failed/aborted runs; cleanup never removes user work. `close()` cleanup owned resources only, preserve diagnostic worktrees by default.

## Events / UI contract (additive event v1)
Keep `currentMilestoneId` scalar; add `activeMilestoneIds: string[]`. Existing role aggregates remain; add `instances: {[id]:{id,agent,milestoneId,status,tool,sessionId,worktree,sandbox}}`.
Existing agent_status/agent_tool/agent_finished gain instanceId; instance_started event includes instanceId,agent,milestoneId,sessionId,worktree,sandbox. Event run_started gains execution. plan_ready includes dependsOn; milestone fields gain dependency/state data. Preserve old consumer schema and totals.
Chat: `chat_message {id,from,to,text,milestoneId?,delivery:'queued'|'delivered'|'rejected'|'unknown',reason?}` and `chat_delivery {id,delivery,reason?}`; bounded `state.chat` array. Sender instance from runner, human from control route. Recipient exact instance ID; unknown or terminal instances rejected clearly, no arbitrary role ambiguity. Durable journal/idle queue: queued means never sent. Attempted sends leave the replay queue; timeout/cancel or thrown/invalid ACK becomes unknown, definitive negative ACK rejected. Emit/journal unknown and return ok:false/error; never automatically replay uncertain sends after detach/attach/finish. ACK budgets: RPC command 5 s, broker 10 s, extension 15 s. Live delivery uses sendMessage; don't return delivered until acknowledged. chat_command_rejected is separate uncorrelated diagnostics for malformed/stale/duplicate commands, never a transcript update. Bound text/count to avoid runaway model chatter.
HITL serialized across lanes; head request only in human/response.json, remaining visible as queued count if feasible. Other independent milestones can continue; role aggregates must not erase active lanes. Abort cancels queued questions and all active processes.
Dynamic replanning is not implemented. The published DAG is immutable; effective maxReplans is 0 and nonzero configured values warn rather than enabling replanning.

## Server / control
POST /api/runs optional fields: `maxParallel`, `sandbox` ('docker'|'host'), `sandboxImage`, `sandboxNetwork` ('bridge'|'none'); host requires `trustedHost:true`. Forward to CLI flags. GET /api/control adds defaults.execution plus `instances` (from state), `recoveryRequired` and recovery metadata where needed.
POST /api/chat body `{runId,to,text}` writes unique atomic command under hive/control/chat/*.json. Response is queued, never falsely delivered; orchestrator consumes and emits chat_message/chat_delivery. Requires same loopback/Host/CSRF checks, active matching run, recipient validation, size limits. No standalone CLI `message` command is implemented; server/tool chat is supported.
Durable run lease: lifecycle module src/core/run-lease.js actual disk owner.json (do not use researcher's guessed lease.json). Server generates SCRANTON_RUN_ID before spawn for BOTH run/demo, use stdio ['pipe','pipe','pipe','ipc'] and env SCRANTON_PARENT_GUARD=1 + SCRANTON_RUN_LEASE. CLI calls registerParentStartup before parsing/config, awaits begin() (scranton-startup-begun) before work and calls refuse() (scranton-startup-refused) on every pre-work exit. guardParent sends scranton-guard-registered. IPC messages carry the lease token. Server releases after child close only with matching refusal and no begun/guard registration; missing or contradictory startup evidence retains the lease. Spawn failure before a PID can safely release. `guardParent({hiveDir,abort,stdin=process.stdin,env=process.env})->dispose({clean=false}={})`; install BEFORE work; EOF/error aborts. Dispose clean only after ALL children/containers stopped. Standalone ownership uses acquireRunLease(hiveDir, info) / releaseRunLease(hiveDir, token). All CLI modes writing Hive must exclude simultaneous owners, including independent CLI vs desktop. Unknown cleanup remains fail-closed, never blind stored-PID kill.
