# Google Antigravity backend integration

Provider ID `google-antigravity`; label `Google Antigravity`; OAuth only, always listed. Existing `google` remains Gemini API key. CLI `antigravity` targets OAuth; canonical `google` and alias `gemini` preserve Gemini key login/logout.

Native provider directory: `src/core/antigravity/`, factory `antigravityProvider(options = {})`; extension entry `extension.js` registers the same native provider with public Pi 1.5.0 `pi.registerProvider(provider)`. Auth runtime registers through public `ModelRuntime.registerNativeProvider(provider)` after creation. No package changes or user profile extensions/settings writes. Child selection explicitly appends `--extension` for this provider only, in both JSON/RPC and tool-less Pipeline paths. `--no-extensions` disables discovery, not explicit extension paths (offline probe required).

OAuth uses Pi's canonical `{type:'oauth', access, refresh, expires, projectId}` credential in its existing locked auth store. Auth surface uses existing single-login lifecycle, timeout, cancel and manual input relay; Antigravity requests the complete redirect URL including code and state, not a bare code. Invalid manual input retries within the same authorization URL/state/PKCE attempt; validated consent denial terminates it. Secrets never become metadata. Provider factory injects HTTP transport for offline tests. Refresh is owned/serialized by Pi runtime, not Scranton's own file writes.

Docker Team Antigravity uses one host inference broker per sandbox invocation. The host retains the full Pi store, refresh token, client identity and access token. Only a random 256-bit invocation capability and broker URL enter the container environment (values are not Docker argv). Docker preparation preflights Pi getAuth through mintAccessToken with minExpiryMs:60000 before creating the broker/container; every authenticated inference resolves it again, so host refresh remains locked and per-request. Preflight and later host-auth failures expose only fixed Accounts re-login guidance (broker HTTP401), never raw diagnostics. Upstream HTTP401/403 also carry safe re-login/account-access guidance. resolveDockerCredential still refuses Antigravity credential export. Pipeline model calls remain on host, unchanged.

Implemented PKCE/token exchange/project discovery and wrapped SSE Gemini inference with Pi transcript/tool converters and event streams. Protocol reference: https://github.com/NoeFabris/opencode-antigravity-auth (OAuth client/scopes, Cloud Code Assist request envelope); independently implemented JavaScript using installed Pi public exports. Limited declared catalog: gemini-3-pro and gemini-3-flash; no entitlement/availability guarantee. ## Docker broker protocol

`broker.js` accepts only POST /inference, application/json and a constant-time-checked Bearer capability. No browser CORS permission. Request JSON has only model, context:{messages}, options. Catalog model IDs only; options allow reasoning/thinking/temperature/maxTokens/toolChoice, never headers, auth, endpoints or commands. Normalized transcript system messages carry tool additions/removals. The host selects its own model and fixed Google endpoint, builds the upstream request and returns bounded NDJSON delta events plus start metadata, per-block start/end data and a complete final Pi message (tools/signatures retained). Cumulative partials are not repeated on the wire. The container reconstructs Pi partial/event objects, text/thinking accumulation, tool arguments and end events. Host writes await write completion, keeping backpressure bounded without the observed drain-wait stall. Container tools execute through Pi, never in broker code. Signed Pro wire IDs use effective low/high thinking tier while transcript/catalog identity stays gemini-3-pro. Adjacent text/thinking deltas coalesce.

Bounds: 16MiB upload, 10000 transcript messages, 4 concurrent inference requests per capability, 64MiB serialized response, 30s request upload, 10s headers, 10min inference deadline. Capability expires after configured agent timeout +10min (maximum24h); closes on runner cleanup even if container removal fails; disconnect/expiry/cleanup abort upstream. Error bodies/diagnostics are sanitized. Network none fails closed. Windows/macOS bind loopback only (Windows Docker Desktop synthetic probe verified loopback via host.docker.internal); native Linux binds only the inspected local default bridge IPv4 gateway, failing closed if unavailable. Linux/macOS execution not dynamically verified. Remote Docker engines are not supported by this local broker design.

`docker-extension.js` is the ONLY additional read-only mount, at /usr/local/lib/node_modules/@earendil-works/pi-coding-agent/scranton-antigravity.mjs to resolve pinned Pi1.5.0 dependencies without modifying/rebuilding image. It contains no Google OAuth code/client secret or credentials. spawnPi rewrites the explicit host provider-extension argument only for sandbox specs declaring providerExtension; host/Pipeline args remain unchanged. Docker --add-host host.docker.internal:host-gateway supplies hostname on Linux too. Other credential env vars are cleared for Antigravity. Agent provider/model/thinking argv still come from configured effective defaults; broker does not apply per-run UI overrides.

Security limits: capability is usable by tools/processes within its container during that invocation (not isolation between those tools), authorizes only bounded catalog inference and is never persisted by Scranton. Plain HTTP is local Docker/host transport, not an encrypted remote transport or egress filter. The image remains allowed cloud networking as before. Pi owns host credential renewal; no real Google endpoint compatibility is claimed by synthetic probes.
