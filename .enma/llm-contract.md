# Scranton LLM contract v1

Entry point: `src/core/llm/index.js`. Own provider-client boundary used by the durable agent and completion bridges. Credential storage/refresh belong to src/core/credentials; no Pi runtime imports.

## Types
Canonical JSDoc lives in `types.js`.
- Context: `{ systemPrompt?: string, messages: Message[], tools?: [{ name, description, parameters: JSONSchema }] }`.
- User: `{ role:'user', content: string | TextBlock[] }`.
- Assistant: `{ role:'assistant', content: Block[], usage, stopReason, errorMessage?, provider, model }`.
- Tool result: `{ role:'toolResult', toolCallId, toolName, content: string | TextBlock[], isError?: boolean }`.
- Blocks: `{type:'text',text,textSignature?}`, `{type:'thinking',thinking,thinkingSignature?}`, `{type:'toolCall',id,name,arguments:object,thoughtSignature?}`. Opaque provider reasoning items may be retained as `providerItem` on thinking blocks for Responses round-trips. Never interpret signatures. Google and Antigravity preserve provider tool-call IDs; absent IDs use `google-call-<random UUID>`, unique across turns. Generate these inside the caller's checkpointed model step; replay uses its saved assistant message, not another provider request. Other live clients require provider-issued IDs and do not synthesize per-response counters; scripted-provider IDs intentionally remain deterministic.
- Usage: `{input,output,cacheRead,cacheWrite,cacheWrite1h?,totalTokens,cost:{input,output,cacheRead,cacheWrite,total,totalFromProvider:false}}`. Input excludes cache reads/writes. Output includes reasoning. USD rates per million tokens; tiers selected by input+cacheRead+cacheWrite strictly above threshold.
- stopReason: `stop | length | toolUse | error | aborted`.

## Interface
`createLLM({ resolveAuth, fetcher? })` returns `{ stream, complete }`.
`stream(model, context, {signal?,auth?,maxTokens?,temperature?,reasoning?,timeoutMs?}={})` returns a single-consumer async iterable with `.result(): Promise<AssistantMessage>`. Iteration and result may be used together; result drains automatically when no iterator is used. Terminal errors are values, not rejected result promises. No retries: durable caller owns retry policy. `complete(...)` is equivalent to `stream(...).result()`.
`model` is a full descriptor or `{provider,model}` ref resolved from catalogue. Full descriptor: `{id,provider,api,baseUrl,contextWindow,maxTokens,reasoning,cost,thinkingLevelMap?}`. APIs: `anthropic-messages`, `openai-responses`, `openai-completions`, `google-generative` (alias `google-generative-ai`), `google-antigravity`, `google-vertex` (API-key express mode; no ADC lookup).
Reasoning: `off|minimal|low|medium|high|xhigh|max`. Defaults off. Unsupported levels are mapped to provider-supported levels. Custom models use explicit full descriptors; custom providers are not read from disk here.

Events preserve the inner assistant-event shape for existing consumers: `{type:'start',partial}`, `{type:'text_start'|'thinking_start'|'toolcall_start',contentIndex,partial}`, `{type:'text_delta'|'thinking_delta'|'toolcall_delta',contentIndex,delta,partial}`, `{type:'text_end'|'thinking_end',contentIndex,content,partial}`, `{type:'toolcall_end',contentIndex,toolCall,partial}`, `{type:'done',reason,message}` or `{type:'error',reason,error:AssistantMessage}`. Toolcall start also includes id/toolName. Snapshots do not mutate after emission. Agent loop wraps block events as `{type:'message_update',message:event.partial,assistantMessageEvent:event}`; start -> message_start, done/error -> message_end. The LLM layer does not write Hive/UI records. Tool arguments accumulate raw deltas and parse only on end; malformed/non-object arguments cause terminal error, never executable calls.

Auth: injected `resolveAuth(providerId) -> Promise<Auth>|Auth`, called once per request unless options.auth supplied. `Auth = {type:'api_key',key:string} | {type:'oauth',access:string,accountId?:string,projectId?:string,mode?:'direct'|'chatgpt'}`. Auth is a client-only projection: never include refresh tokens, expiry, client IDs, scopes, grant metadata or arbitrary stored fields. Valid stored access tokens resolve without a lock or write; refresh re-reads credentials under the cross-process lock, and an unchanged transaction does not rewrite the store. Resolver owns storage, refresh and Antigravity provisioning; clients never import OAuth modules. Anthropic OAuth uses subscription headers/system prompt/tool name mapping; OpenAI OAuth defaults to the direct-use api.openai.com Responses path studied in the former pi-ai 1.5.2 protocol (`chatgpt.tokens.use.direct` scope). Legacy backend credentials explicitly set `mode:'chatgpt'` and `accountId`; this selects chatgpt.com/backend-api/codex/responses with subscription headers. Never guess token type from its spelling. Antigravity requires projectId. Missing credentials fail permanently. No implicit environment/file credential lookup.

Error classification: `classifyError(error) -> {transient,status:number|null,code:string,message:string}`. 408/429/5xx, network failures/timeouts transient; 400/401/403, protocol errors and caller abort permanent. Final assistant adds `error` with this classification. Public HTTP errors contain status and a normalized code only, never provider response bodies or credentials. HTTP 413 and recognized HTTP 400 context/token-limit bodies (Anthropic, OpenAI/compatible, Google and Antigravity) map to permanent `CONTEXT_WINDOW_EXCEEDED`; only caller compaction can retry with a smaller context. Error-body inspection is capped at 64 KiB and cancels the remainder. A bounded JSON HTTP 400 `error.code:model_not_found` maps to permanent `MODEL_NOT_AVAILABLE` with safe guidance to select an account-supported model; no provider message is exposed. Other 400 errors remain permanent `PROVIDER_ERROR`.

Credential error codes (safe fixed messages; never expose raw diagnostics):
- Transient: `SCRANTON_OAUTH_TEMPORARY` (network/timeout, provider renewal unavailable or insufficient requested validity), `SCRANTON_CREDENTIAL_LOCKED` (cross-process lock contention). Raw network codes, including `NETWORK_ERROR`, `ECONNRESET`, `ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`, `ETIMEDOUT`, `ENETUNREACH`, `EHOSTUNREACH`, `EPIPE`, and `UND_ERR_*`, remain transient.
- Permanent: `SCRANTON_AUTH_MISSING` (message: `Provider credentials are missing; sign in or configure an API key`), `SCRANTON_OAUTH_REJECTED` (revoked/rejected refresh; sign in again), `SCRANTON_CREDENTIAL_INVALID`, `SCRANTON_CREDENTIAL_STORE` (fail closed on invalid/unavailable storage), `SCRANTON_AUTH_ABORTED`, `SCRANTON_AUTH_LOGIN`, `SCRANTON_AUTH_URL`, `SCRANTON_AUTH_BROWSER`, `SCRANTON_OAUTH_DENIED`, `SCRANTON_PROVIDER_INVALID`, `SCRANTON_PROVIDER_CONFLICT`. Explicit credential codes take precedence over HTTP status classification. Caller abort remains permanent; resolver renewal deadlines are temporary.

Anthropic manual authorization input must contain the matching state, as exactly `code#state` or the complete redirect URL. Missing/mismatched state is rejected before token exchange, with a corrective prompt.

## Scripted provider
`createScriptedProvider(turns)` returns `{stream,complete,calls}` with same signature (no auth). Each turn `{content?:Block[],text?:string,thinking?:string,toolCalls?:[{id?,name,arguments}],usage?:Partial<Usage>,stopReason?,error?:{message?,status?,code?},delayMs?:number,chunkSize?:number}`. Turns consumed in call order; exhaustion is terminal permanent error. `calls` contains cloned `{model,context}` only (no auth/options). Delay and chunk iteration honor abort. Defaults deterministic tool ids. Suitable for agent-loop tests/demo.

## Catalogue
`models` static snapshot derived from the historical Anthropic/OpenAI/Google pi-ai 1.5.2 catalogue plus Scranton Antigravity; `getModel(provider,id)`, `resolveModel(ref)`, `calculateCost(model,usage)`. Catalogue date/version and MIT attribution in THIRD_PARTY_NOTICES.md. `account-models.json` adds the separate ChatGPT/Codex OAuth snapshot, Vertex API-key models and GPT-6.2 Sol metadata from official OpenAI documentation (2026-11-22). `accountModels(provider,auth)` uses the exported `isChatGPT(auth)` predicate (`mode === 'chatgpt'`) shared by selection, listing and request routing. Credential account metadata projects the same safe `mode` as client auth. Only ChatGPT-mode OAuth uses that snapshot; direct OAuth (including missing mode) and API keys keep the OpenAI API catalogue. ChatGPT transport rejects refs absent from its supported list before fetching. `newestModels` explicitly marks the newest supported catalogue models; Automatic retains provider priority Anthropic, OpenAI, Gemini, Antigravity, then Vertex. Current markers are Opus 5.5, GPT-6.2 Sol (user choice), Gemini 4 Argon, Gemini 3.8 Flash, Gemini 4 Argon. Antigravity's latest marker uses its advertised thinking variant wire IDs; disabled Gemini 4 entries are excluded. This is deterministic offline selection, not live entitlement discovery or continuous release tracking. New releases require a catalogue update. No discovery/network on import. Unknown refs fail explicitly.
